# 关键字驱动

## 关键字驱动设计模式介绍

在整个自动化测试领域下，有且只有两种设计模式。

1. 关键字驱动
2. POM

之前学习中所使用到的自动化测试，都属于线性代码的领域。代码的维护工作以及可拓展性都相对比较麻烦。所以在实际企业中我们所有的自动化基本都是基于测试框架的形态来实现的。因为可以更加灵活简便，且在维护过程中会非常节省时间。要实现测试框架一定要使用设计模式。

关键字驱动设计模式，总体来说是属于传统的自动化测试技术体系。通过实现一个框架。来解决不同项目的自动化测试需求。也就意味着关键字驱动实现的测试框架是一种可以以一对多的测试框架形态。

```python
def 刷花(学员):
  if 学员 == 听懂了:
    return 花
  else:
    return 问题
```

关键字驱动其实就是通过自主封装自定义函数，来解决各类重复的测试行为，将所有重复性为变得更加简单，让程序具备有灵活性，降低代码冗余。

关键字驱动一定是选择重复率高，相对复杂的操作形态的代码进行自定义的封装。

关键字驱动形态下，一般封装分为两类：

1. 依照操作行为进行的封装，一般而言，此类会用的更多。
2. 依照操作流程进行的封装

## 关键字驱动设计模式原理

所有的测试框架，通用的结构形态：

1. 数据与代码的分离
2. 逻辑代码与测试代码的分离
