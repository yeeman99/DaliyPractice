# Excel数据驱动

## 数据驱动

在整个自动化测试领域下，都是基于两种设计模式来完成的自动化测试代码的底层结构。在实际的测试过程中，我们会需要使用到非常多的测试数据。来满足我们的测试业务流程的顺利执行。我们为了考虑整体测试框架的维护性以及对测试数据的管理，所以会选择将数据独立出来，进行单独管理。从而来实现数据驱动代码的模式。这个就是数据驱动。（其实就是基于文件来管理测试数据。）

常见的数据驱动模式：

1. Excel数据驱动：
   1. 优势：学习成本很低，代码需求很低。方便没有技术的人员来快速上手使用。
   2. 劣势：维护成本相对较高（相比较其他数据驱动模式而言）
   3. 优先推荐到没有自动化测试技术体系的公司团队，以及说对于整个公司在自动化测试能力相对很弱的情况下，可以使用此方式快速实现自动化测试的推行。
2. Yaml、Json、Py：
   1. 优势：轻便灵活，极其简单的维护工作。可以非常高效地完成自动化测试的数据准备需要。
   2. 劣势：学习成本太高了。
   3. 推荐在有自动化测试技术沉淀的公司或者团队，对于有掌握自动化技术的团队来进行优化和升级的时候可以使用。
3. 数据库数据驱动
4. txt、xmind其他的一些数据驱动方式
5. 创造数据实现数据驱动

不同的数据驱动形态，决定了自动化测试框架的交互形态。所以选择数据驱动的时候一定要结合实际情况而定。

## Openpyxl库介绍

在Python中操作excel文件的库有很多。我们在实际课堂中讲解是基于Openpyxl库来实现。xlrd和xlwt已经过时了。pandas主要是用于做excel数据采集和分析的。

环境部署：

- pip install openpyxl

openpyxl库没有自动补全功能。也就是大家在调用此库的方法时，需要自己记下来。
