# HTTP网络协议

## HTTP网络协议介绍

目前市场最核心的网络协议就是HTTP。版本是1.1为核心。基本上所有的网络协议，在数据的通信和交互上，都不会有太大的区别。

当你启动一个浏览器，实现对某个URL的访问时，请问你的浏览器经历了哪些步骤？

1. 浏览器进行url的解析。
2. 建立一个临时的TCP连接通道。
3. 发送数据
4. 服务端基于对应的接口来获取数据并进行计算和处理。
5. 生成结果并基于原有的通道原路返回。关闭连接通道。
6. 接收数据，并且进行解析。
7. 进行页面的渲染，展示在用户眼前。

HTTP网络协议本身属于应用层协议。底层协议实现还是基于TCP来实现的。目前HTTP网络协议被称为是人机交互效率最高的一种网络协议。因为HTTP是无状态网络协议。无状态也就意味着每一次的请求都是独立的个体。所有请求之间，没有任何的关联。

HTTP网络协议包括HTTP和HTTPS两大类。

1.  两者之间基本一致。HTTPS就是HTTP+SSL证书。加强了HTTP的安全性的一种手段。
2. HTTPS	虽然安全性更高。但是因为SSL证书的存在，所以在每一次请求的时候会耗费更多的资源。很多时候在请求的时候是不需要ssl证书的。所以不会在整个过程中全部使用https网络一些。
3. 两者的辨别方式是通过url来进行辨别的。

url:

1. 网站，网址，链接。。。其实url的全称叫做统一资源定位符。功能类似于xpath。接口也是通过url来进行区分的。 不同的url可以支持我们访问到不同的接口。
2. 网络协议://IP:Port/path?args1=xxx&args2=aaa
3. https://www.baidu.com/s?wd=123&rsv_spt=1&rsv_iqid=0xd2fbe62400392173&issp=1&f=8&rsv_bp=1&rsv_idx=2&ie=utf-8&tn=baiduhome_pg&rsv_enter=1&rsv_dl=tb&rsv_sug3=3&rsv_sug1=1&rsv_sug7=100&rsv_sug2=0&rsv_btype=i&prefixsug=12%2526lt%253B&rsp=7&inputT=305&rsv_sug4=305
4. http的默认端口是80，https的默认端口是443
5. path是接口路径
6. url在另外一种请求方法下不会带参数在url中显示。。

## 请求与响应详解

### 请求

用户端下发至服务器的数据。叫做请求。request。

一般而言，请求分为三个部分的内容：

1. 请求行：
   1. 请求方法：不同的接口有不同的请求方法。我们在请求发送时，请求方法必须与被请求的接口保持一致。接口本身的请求方法在接口文档有明确定义。
      1. get：一般是用在数据的展示。不会涉及到任何的关于数据的修改、校验、新增等操作
         1. 所有的参数都是明文显示在url的后方。通过?进行链接。（也可以将参数不明文显示）
         2. 请求的长度是有限制的。（其实是URL有长度限制。而不是get请求本身。）
         3. 安全系数相对较低
         4. 数据可以被缓存
      2. post：一般用于表格的提交。数据的修改和新增
         1. 参数不会明文显示在url后方。而是放在body之中。
         2. 长度没有限制。（因为数据存放在body之中）
         3. 安全系数相对更高
         4. 无法被缓存
   2. url：显示本次请求的接口url
   3. 版本信息：显示当前是基于哪一个版本的http协议来进行的数据传输
2. 请求头：request headers
   1. 用于通知服务端，请求的数据格式以及规范。
   2. 用于添加额外的数据。一般而言额外数据都是自动添加的。
   3. keep-alive：http1.1的时候才有的设置。长连接，核心是通道
      1. 将原本一次性的tcp临时链接通道转为长期通道。可以持续保持下去。只要用户在继续与系统交互。则该通道一直存在，否则销毁。
      2. 长连接和无状态没有任何关系。
3. 请求体：request body
   1. 仓库。用来保存本次请求需要传递的数据。（数据加密一般是前端的操作。和请求体没有关系。）

### 响应

服务端返回至用户端的数据结果。叫做响应。response。

响应分为三个部分：

1. 响应行：
   1. 版本信息
   2. 响应状态码：status code。用于表示本次请求的运行结果（只与请求本身有关，与业务无关。）
      1. 100，基本看不到。表示请求已被接收，正在继续处理中。
      2. 200，表示成功，响应已经返回。
      3. 301，表示重定向，当前请求的资源转移到了另外一处。
      4. 404，表示访问的接口路径不存在。要么是调用接口是url写错了。要么是指向的服务未部署
      5. 500，服务器内部异常。
2. 响应头：response headers
   1. 与请求头类似，定义规范和格式
   2. 告知客户端如何处理特定的数据
      1. Set-Cookie表示用户端本地保存至cookie文件之中。
3.  响应体：response body
   1. 生成的响应结果保存位置。（响应结果一般都是文本的格式。一般在接口测试阶段，断言的内容就是这一块。）

## Cookie、Session、Token

HTTP网络协议是无状态协议。

### cookie

cookie本身是一个本地文件。用于管理和存储各个网站的相关内容的。整体内容是基于键值对kv形态来进行管理。可以存放指定的服务端和响应头信息。

### Session

临时会话机制。不同的用户在访问系统的时候会生成不同的会话框。该用户的所有交互和数据传递都是基于该Seesion会话框来进行管理的。session会话都是基于服务端来进行管理的。不同的会话框有不同的独立id信息。也就是SessionId。服务端管理会话，将sessionid传递至对应用户本地，保存在cookie之中。用户请求时，带上sessionid即可让服务器识别具体的会话框。每次用户请求时基于sessionid来作为鉴权的手段。

### Token

临时身份令牌。用户获得系统授权之后，系统返回一个token令牌。保存在本地cookie之中。后续的每一次请求都会带上token值。通过对token值的校验来判断你是否授权。
