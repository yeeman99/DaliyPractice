# Pytest下的测试报告

（主要分为以下两种）

```
pytest-html测试报告生成：
        生成测试报告，需要额外添加指令 --html=测试报告名称.html即可。一定记得测试报告的名称后面要添加后缀名
        默认情况下测试报告是不会加载任何的log信息的。如果说要在测试报告中添加log信息，一定要添加指令：
            --capture=sys
        整体而言，测试报告分为两个部分。一个是html测试报告的本身。另外一个assets文件夹和其中的css文件。
        assets文件夹是必须存在的内容。因为其中包含有测试报告的html文件的样式内容。
        如果想要发送html测试报告，有两种方式：
            1. 将assets文件夹和html测试报告打包压缩。共同作为压缩包的内容以附件进行发送
            2. 添加额外指令 --self-contained-html，将原有的assets文件夹内容融合到html文件之中，形成
                一个单独的文件。
        如果说生成的html测试报告，需要有单独的保存路径，记得在--html=后方添加完整的保存路径即可。
        如果想要让pytest-html成为默认的测试报告形态，我们可以在pytest.ini中进行配置。
'''
```

## pytest-html测试报告生成

pytest下的自带默认的测试报告模块。这个报告会直接生成一个html格式的文件。因为是默认自带的测试报告模块，所以不需要额外进行任何的安装。

（unittest的测试报告--html，testrunner，htmlreportcn,beautyfulreport）

## Allure测试报告生成

Allure测试报告，自动化测试报告中的天花板。领导最喜欢的测试报告。本身属于一个独立的测试报告插件。因为可以支持到python和java的自动化测试报告生成。所以环境部署的步骤会有些许差别。

### 环境部署

- allure测试报告的插件安装：
  - 下载allure测试报告的安装包。（网盘里有。也可以在GitHub上下载，或者百度搜索官方渠道下载。）然后进行安装。解压到指定的路径之后，进入到allure的安装路径下的bin路径之中，复制完整的bin路径添加到系统环境变量path之中
  
- 安装jdk（网盘有，也可以选择在jdk官网下载）。具体安装步骤大家百度搜一下。一定注意安装的jdk版本。如果你搞不清楚jdk版本的问题，就选择jdk11
  - 校验安装：在cmd中输入java -version，如果显示版本信息，则安装成功
  
- 校验allure环境：
  - 在cmd中输入allure --version，如果显示版本号，则安装成功
  
- allure-pytest插件：
  - pip install allure-pytest
  
  ```
  Allure测试报告生成：
      1. 搭建allure测试报告的环境
      2. 生成allure测试报告的数据，需要添加指令 --alluredir=测试数据的保存路径。实现对测试过程中产生的结果数据进行记录
      3. 生成allure测试报告：
          1. 指令 allure serve json数据的保存路径
              生成临时的allure测试报告。并且启动一个web server。可以基于你本地的ip生成一个web服务，提供内网的访问权限。
              让局域网内的其他成员可以通过你的web地址对测试报告进行直接访问和浏览。
              同时，会有一个临时的allure测试报告生成。会保存在默认的临时路径之中。该报告生成时是以一个前端工程的结构形态来生成的。
              该保存路径无法修改。也无法直接通过访问index.html文件实现对该报告的访问。
              只能通过web server实现对测试报告的访问和浏览。也就是基于http://IP:Port来实现访问。
              一般此指令是用于临时调试或者提供给组内成员查看本次结果的一种有效手段。
          2. 指令 allure generate json数据的保存路径 -o allure测试报告保存路径
              将测试报告保存在指定的路径。可以直接通过pycharm进行访问。但是对于文件夹中直接访问依旧不会有任何数据的加载。
          所以allure测试报告无法通过压缩之后以附件的形式进行邮件发送。（不支持静态访问）
          allure测试报告生成是无法通过pytest.ini进行配置的。
          allure测试报告在生成之后会有一个前端工程的文件夹。在访问该工程的index内容时，有部分内容会无法加载，或者无内容。
          这是正常现象。可以忽略不用纠结。后续在jenkins集成后，就会有所有内容的展示了。
  
          pytest+allure的技术体系。个人更加推荐在关联jenkins之后来实现完整的执行和使用。因为在这种场景下，所有的
          功能都可以正常满足到你的需求。如果想要单独使用，建议通过web server的形态提供给到团队成员进行访问。
  
          allure测试报告生成：
              基于pytest生成allure测试报告所能够识别的allure测试数据，然后基于allure指令将数据加载至allure测试报告之中
  ```

## Fixture下的传参

```
fixture下的传参：
    fixture本身就是一个函数。只要是函数，就一定可以接收参数。因为特定的场景下Fixture一定需要接收参数。
    所以需要解决Fixture的传参问题。
    1. 将Fixture中需要的数据通过其他Fixture的return形态来实现数据的返回。
    2. 通过request参数实现对数据的接收
```
